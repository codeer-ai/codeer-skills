# Support operating models

Classify the support operation before selecting task modules. A company can combine multiple models.

| Operating model | Primary customer outcomes | Common task modules |
|---|---|---|
| Appointment-based service | find, book, prepare, change, attend | appointment; advice/eligibility; billing |
| Order and fulfillment | choose, purchase, track, receive, return | order; billing; complaint |
| Account and subscription | access, configure, renew, pause, cancel | account; billing; technical |
| Professional advice and triage | assess fit, urgency, next step, follow-up | advice/triage; appointment; records |
| Technical support | diagnose, recover, configure, escalate | technical; account; records |
| Regulated transaction | verify, authorize, transact, dispute, document | billing; account; records; complaint |
| Marketplace or multi-party coordination | match, verify, coordinate, allocate responsibility | appointment/order; complaint; records |
| Field service or repair | diagnose, schedule, dispatch, quote, complete, warranty | technical; appointment; billing |
| Membership or entitlement service | establish eligibility, consume benefits, renew, appeal | account; advice/eligibility; billing |

## Classification procedure

1. Identify what state the customer is trying to change.
2. Identify which party owns each state and action.
3. Identify prerequisites, irreversible transitions, deadlines, and handoffs.
4. Select two or three dominant operating models rather than forcing a single industry label.
5. Load only their relevant task modules.

Do not infer the task distribution from industry name alone. A veterinary hospital, salon, visa service, and repair center can all share appointment mechanics while differing sharply in risk.
